# E2: Repository pipeline trace

Member: ____________
Time budget: 7-9 hours

## Goal

Run the project on the host. Follow one token from the model file to output text.

## Phase 1: Read the Repository (2-3 hours)

Read https://github.com/slvDev/esp32-ai in this order:

1. The repository README.
2. `RESULTS.md`.
3. `firmware/esp32_barista/README.md`.
4. `firmware/esp32_tinystories/README.md`.

Record the project purpose, the 28.9M parameter model, and the published `9.88 tokens per second` result. Write the summary in your own words.

## Phase 2: Install and Build (2-3 hours)

1. Install Python 3 and `uv` from the project files.
2. Install the project with `uv` and the lock file.
3. Run `pytest` and record the test count and result.
4. Run `scripts/fetch_model.sh` with the TinyStories model.
5. Run `scripts/benchmark_device.py` when it supports host execution.

Do not install ESP-IDF this week. Do not use a board. Record exact commands, versions, and errors.

## Phase 3: Trace One Token (2-3 hours)

Answer these questions from the code:

1. Which script downloads the model?
2. What model file format does the script create?
3. What do `src/model.py` and `src/quantize.py` do?
4. Where does the runtime read weights for one token?
5. Where does the runtime select the next token?
6. Which tokenizer changes the token into text?
7. Which steps run on the host and which steps need the board?

Write the token path as a numbered sequence. Name each file and function that you find.

## Phase 4: Write `PIPELINE.md` (1-2 hours)

Write at least 300 words. Use `## Project Summary`, `## Toolchain`, `## Build Results`, `## Token Path`, and `## Host and Board Work`.

Include the build log, test result, model fetch result, and the complete token path. Do not include any downloaded model.

## Evidence Checklist

- [ ] `PIPELINE.md` contains the build log.
- [ ] `PIPELINE.md` contains at least 300 words.
- [ ] `PIPELINE.md` contains test and model fetch results.
- [ ] E1 reviewed the report.
