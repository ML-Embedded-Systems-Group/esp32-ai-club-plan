## Phase 1: Reading the repo (about 2-3 hours)

The project: https://github.com/slvDev/esp32-ai

A 28.9M parameter language model on an ESP32-S3, running at 9.88 tokens per second. The published numbers are in RESULTS.md.

Read in this order:

1. The repo README.
2. RESULTS.md.
3. firmware/esp32_barista/README.md and firmware/esp32_tinystories/README.md.

For each source, write in your log:
- what it is, in one line
- 3 things you learned
- 1 question you still have

Write in your own words. Do not copy-paste.

## Phase 2: Toolchain and build (about 2-3 hours)

Install what the repo needs:

1. Python 3 and uv, per pyproject.toml and .python-version in the repo.
2. Install the project with uv, per the lock file.
3. Run the test suite with pytest. All tests in tests/ must pass.
4. Run scripts/fetch_model.sh with the tinystories model. It downloads and verifies the model into artifacts/.
5. Run the host-side benchmark: scripts/benchmark_device.py, if it runs without a board.

The firmware itself needs the ESP-IDF toolchain and a real board. Do not install ESP-IDF this week. Everything you run must work without hardware.

Write the build log: the exact commands, the versions, and the test results.

## Phase 3: Trace the pipeline (about 2-3 hours)

Follow one token from the model file to the output. Answer these questions from the code:

1. Where does the model come from: which script downloads it, and what format is it in?
2. How does src/ prepare the model: what do model.py and quantize.py do?
3. What does the runtime do per token: where does the loop read the weights, and where does it sample the next token?
4. How does the token become text: find the tokenizer and the output path.
5. What runs on the host today, and what runs only on the board?

## Phase 4: Doc generation, PIPELINE.md (about 1-2 hours)

Write PIPELINE.md by hand, in your own words, at least 300 words. No drawings.

Required sections:

Write every sentence yourself. Do not paste from any AI tool.

Push PIPELINE.md to this repo. Do not push any downloaded model.
