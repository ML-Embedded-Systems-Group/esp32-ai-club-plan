## Phase 2: Coding, TIMING_CALC.py, the timing calculator (about 2 hours)

The club converts measured reads into tok/s with this script, on any machine or chip. Build it now:

1. Write a script, under 30 lines, stdlib only (math, sys).
2. It takes the average read time in microseconds and the rows per token, default 6, as arguments.
3. It prints: read time per token in us (rows times the read time), per token in ms, the tok/s (1,000,000 divided by us per token), and the row-read share of one token time (row reads divided by token time at 9.88 tok/s, times 100).
4. Run it with 20.3 us and 6 rows (the chip numbers). Keep the output.
5. Run it with your own measured read time from H1's FLOW_BENCH.py if you have it. Keep the output.

Save it as TIMING_CALC.py. Write the script yourself. Do not paste from any AI tool.

## Phase 3: Maths, timing (about 2 hours)

Show every step, with units:

1. One token at 9.88 tok/s: 1 divided by 9.88, in seconds. Convert to milliseconds.
2. Row reads: 6 rows times 20.3 us. Convert to milliseconds.
3. Share: row reads divided by the token time, times 100. Round to 2 decimals. Is it large or small?
4. Build a table for 5, 9.88, and 20 tok/s: ms per token, and the row-read share as a percentage.
5. If the read time halved to 10.15 us: the new share. Does tok/s change meaningfully? Write why not.
6. Write 2 sentences: what dominates the token time, and why row reads still matter.
