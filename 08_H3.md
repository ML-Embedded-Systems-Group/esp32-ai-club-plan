## Phase 2: Maths (about 2 hours)

Problem 1: compute the size of the header prefix, before the metadata starts: the magic, the version, the tensor count, the metadata count. Show every step with each field's size.

Verify: the prefix is 24 bytes: 4 + 4 + 8 + 8.

Problem 2: compute the byte size of one tensor entry: the name length field, the name bytes, the dimensions count, the dimensions, and the type. Use a 2-dimensional tensor named "test". Show every step.

Verify: the entry size must match what your script writes, byte for byte.

This is the meeting check. The lead asks you 2 questions from this phase.

## Phase 3: Coding, GGUF_REPRO.py (about 2-3 hours)

Write a script, under 80 lines, stdlib only (struct):

1. Writer: build a minimal GGUF file with 2 tensors per the spec: magic, version, tensor count, metadata count, then per tensor: name length, name, dims count, dims, type. Write it with struct.pack, byte by byte. Save as mini.gguf.
2. Print the byte offsets: where each field starts, from the spec's layout.
3. Reader: parse mini.gguf with struct.unpack, strict: the magic must equal GGUF, then version, counts, then every tensor.
4. Verify: every parsed value equals what the writer wrote. Print round trip: pass or fail.
5. Verify the offset math from phase 2 against the real file: print the byte position of the first tensor name.

Save it as GGUF_REPRO.py. Write the script yourself. Do not paste from any AI tool.
