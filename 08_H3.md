## Phase 2: Maths, the header layout by hand (about 2 hours)

Show every step:

1. The file starts with the magic: 4 bytes, "GGUF".
2. Version: uint32, 4 bytes.
3. Tensor count: uint64, 8 bytes.
4. Metadata count: uint64, 8 bytes.
5. Header prefix size: add 4 + 4 + 8 + 8. How many bytes before the metadata starts?
6. One tensor entry: name length (uint64) + name bytes + dimensions count (uint32) + dims (4 bytes each) + type (uint32). Compute the entry size for a 2-dimensional tensor named "test" (4 bytes).
7. Write 2 sentences: why the format has fixed-size fields, and what an offset is.

## Phase 3: Coding, GGUF_REPRO.py (about 2-3 hours)

Reproduce the spec: write a valid file, read it back:

1. Write a script, under 80 lines, stdlib only (struct).
2. Writer: build a minimal GGUF file with 2 tensors per the spec: magic, version, tensor count, metadata count, then per tensor: name length, name, dims count, dims, type. Write it with struct.pack, byte by byte. Save as mini.gguf.
3. Print the byte offsets: where each field starts, from the spec's layout.
4. Reader: parse mini.gguf with struct.unpack, strict: the magic must equal GGUF, version, counts, then every tensor.
5. Verify: every parsed value equals what the writer wrote. Print round trip: pass or fail.
6. Verify the offset math from phase 2 against the real file: print the byte position of the first tensor name.

Save it as GGUF_REPRO.py. Write the script yourself. Do not paste from any AI tool.
