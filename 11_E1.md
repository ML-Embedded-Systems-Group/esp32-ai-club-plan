# E1: Embedded, week 1

Member: ____________
Time budget: 8-12 hours across the week.

## What this week gives you

You run every stage of the project yourself with a small model: data, training, evaluation, quantization, and the C runtime. Then you trace one token through the C runtime line by line. By the meetup you can explain every stage from memory, with your own numbers.

## Part 1: Run the full pipeline (about 5-6 hours)

Paste the real output of every command into your log. Do not paraphrase.

1. Fork the repo, clone it, and set up the env with `uv sync`.
2. Run the data step: `uv run python -m research.tinystories.prepare --vocab 32768`
   Record how long it takes, the size of the raw folder, and the tokenizer vocab size.
3. Train a small model on Colab: `uv run python -m research.tinystories.train --arm baseline --vocab 32768 --steps 200 --target-core 559000 --seed 0`
   Record the loss at steps 50, 100, 150, and 200. Save the checkpoint to Drive.
4. Sample from your model: `uv run python -m research.tinystories.sample --run runs/<your-run>.pt --tokenizer data/tinystories/vocab-32768/tokenizer.json`
   Save 5 generations and note the quality.
5. Run quantization: `quantize_eval.py` on your run. It will refuse. Record the error message and explain why the tool refuses a single-arm cohort. Read src/quantize.py to find the rule.
6. Build the portable C runtime on host and run its tests. Record the max abs diff.
7. Write PIPELINE_LOG.md with the commands, the outputs, and the errors. Push it to this repo in a PR.

## Part 2: Your depth, one token through the runtime (about 4-5 hours)

1. Install the ESP32 toolchain (Arduino ESP32 core 3.3.10 or ESP-IDF).
2. Compile the bandwidth benchmark firmware on host. Compile only, no flash. Record the compile log.
3. Trace one token from input to logits in the C runtime. For each stage, write: the function name, the file and line numbers, the tensor shapes, and where the memory lives (SRAM, PSRAM, flash).
4. Mark on the trace where the 6 PLE rows are read from flash and where the head scans PSRAM.
5. Deliverable: TOKEN_TRACE.md with the per-stage table and the compile log. Push both to this repo.

## Part 3: Learn with proof (about 2 hours)

1. Draw the ESP32-S3 memory map by hand on paper: 512 KB SRAM, 8 MB PSRAM, 16 MB flash. Label where each model weight lives. Photograph it and add it to your log.
2. Read the first 100 lines of the runtime main loop. Write in your own words what happens from reset to first generated token.
3. Write one paragraph: the hardest thing you learned this week and why.

## Part 4: Meetup teach-back

- 10-minute talk with your own numbers: the trace table, the golden diff, the compile log.
- The lead asks two questions about your log. You answer from the log, not from memory.
