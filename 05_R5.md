## Phase 2: Coding, ERROR_STUDY.py, the sweep tool (about 2-3 hours)

The club picks its group size from this tool's table. Build it now:

1. Write a script, under 60 lines, stdlib only (math, random, struct, csv).
2. Generate 1000 random values between -1 and 1. Write them to RAW.bin as fp16 with struct.pack (2 bytes per value).
3. For group sizes 1, 2, 4, 8, 16, 32: read RAW.bin, quantize every group to 4-bit levels with one scale per group, dequantize.
4. For each group size compute: bytes used, sum of absolute errors, maximum absolute error, and the error relative to the group 1 error as a percentage.
5. Print a table, one row per group size.
6. Also write the table to a CSV file, results.csv.
7. The script must accept a file name argument, so the club can run it on real weights in week 2.

Save it as ERROR_STUDY.py. Run it. Write the script yourself. Do not paste from any AI tool.

## Phase 3: Maths, bits accounting (about 2 hours)

Show every step, for the 1000 values:

1. fp16: 1000 values times 16 bits. Total bits, then bytes.
2. Group 1: 1000 times 4 bits, plus 1000 scales times 8 bits. Total bits, then bytes.
3. Group 4: 1000 times 4 bits, plus 250 scales times 8 bits. Total bits, then bytes.
4. Group 16: 1000 times 4 bits, plus 63 scales times 8 bits. Total bits, then bytes.
5. Group 32: 1000 times 4 bits, plus 32 scales times 8 bits. Total bits, then bytes.
6. Compression ratio vs fp16 for groups 4, 16, and 32: total bytes divided by fp16 bytes. Round to 2 decimals.
7. Scale overhead: the scale bytes as a percentage of the total bytes, for group 4 and group 32.
8. Write 2 sentences: why bigger groups use fewer bits, and what that costs.
