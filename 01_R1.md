## Phase 2: Coding, RESULTS_CHECK.py (about 2 hours)

The club checks every results file with this script. Build it now:

1. Download the raw results file: https://raw.githubusercontent.com/slvDev/esp32-ai/main/RESULTS.md . Save it as RESULTS.md in your working folder.
2. Write a script, under 60 lines, stdlib only.
3. Read RESULTS.md line by line. For each table row (lines that start with |), split the cells and collect the label and the numeric cells.
4. Print every row: the label and the numbers.
5. Derive for each row with a tok/s number: ms per token (1000 divided by tok/s). Print it next to the row.
6. Derive for each row with a ppl number: the loss it implies, math.log(ppl). Print it.
7. Count the rows parsed and print the count. If a row has no numbers, print a warning with the label.
8. The script must work on any results file with the same shape. The club runs it on its own numbers next week.

Save it as RESULTS_CHECK.py. Run it. Write the script yourself. Do not paste from any AI tool.

## Phase 3: Maths, compression and capacity (about 2 hours)

The model file is 14.9 MB at 4 bits per value. Show every step, with units:

1. Bytes per value at 4 bits. Compute the number of values: 14.9 MB in bytes, divided by bytes per value.
2. Sizes for 4 bit depths: 16 bits (fp16), 8 bits, 4 bits, 2 bits. Build a table: bit depth, bytes per value, total MB.
3. Mark in the table which sizes fit in flash 16 MB. Which do not fit?
4. Compression ratio: fp16 size divided by 4-bit size. Compute the savings as a percentage: 1 minus 4-bit size divided by fp16 size, times 100.
5. Vocab index: 15 bits per token. Bytes per token: 15 divided by 8. Size for one million tokens, in MB.
6. Write 2 conclusions: which bit depth makes the model fit the chip, and what the savings percentage means in one sentence.
