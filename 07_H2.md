## Phase 2: Coding, MEMORY_BUDGET.py, the placement tool (about 1-2 hours)

The club uses this to check any model file against the board. Build it now:

1. Download the real model file: https://github.com/slvDev/esp32-ai/raw/main/src/model.bin . Save it as model.bin in your working folder.
2. Write a script, under 30 lines, stdlib only (os, math).
3. Get the model size with os.path.getsize. Print it in MB.
4. Print a budget table: flash 16 MB (fits? free space), PSRAM 8 MB (fits? free space), SRAM 512 KB (fits? free space).
5. For each tier print a verdict line: fits or does not fit, with the numbers.
6. The script must work for any model file, so the club can run it on every candidate model.

Save it as MEMORY_BUDGET.py. Run it and keep the output. Write the script yourself. Do not paste from any AI tool.

## Phase 3: Maths, ratios (about 1 hour)

Show every step:

1. SRAM 512 KB: how many times does it fit into flash 16 MB? Divide 16 MB by 0.5 MB.
2. PSRAM 8 MB: how many times does it fit into flash?
3. The model is 14.9 MB. What percentage of flash is it? Divide 14.9 by 16, times 100.
4. Does 14.9 MB fit into PSRAM? Show why not.
5. Two sentences: why the table lives in flash and the head in PSRAM.

## Phase 4: Doc generation, MEMORY_POSTER.md (about 1 hour)

Build MEMORY_POSTER.md with these parts:

- The output of MEMORY_BUDGET.py.
- A poster version: draw the 3 tiers to scale with the model parts placed. Use https://excalidraw.com or a drawing tool. Export as PNG, embed it. The parts: model.bin in flash, head in PSRAM, active computation in SRAM.
- The maths from phase 3, every step.

Push MEMORY_POSTER.md, MEMORY_BUDGET.py, and model.bin to this repo.
